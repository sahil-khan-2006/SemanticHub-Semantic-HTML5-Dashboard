    Accordion

    Single-expand accordion using aria-expanded + aria-controls.

    Using elements like <header>, <nav>, <main> and <table> so assistive tech understands structure without extra ARIA.

    Dialogs trap focus, return focus to the trigger on close, and pages move focus to the <h1> on navigation with an aria-live announcement.

    WCAG AA requires 4.5:1 for normal text and 3:1 for large text and UI components. This theme exceeds 7:1 for body copy.

    Tabs (roving tabindex)

    Arrow-key navigation with role="tablist" pattern.

    Tabs group related content. Only one panel is visible; arrow keys move between tabs per WAI-ARIA Authoring Practices.

    Use ← → to move, Home / End to jump. Activation is automatic on focus.

    <div role="tablist">…<button role="tab" aria-selected="true">

      Northwind Enterprise Dashboard

      A professional, responsive, multi-page enterprise dashboard demonstrating Semantic HTML5 and WCAG 2.1 AA accessibility with vanilla HTML + CSS + JS — zero frameworks.

      Pages included

      • index.html → Dashboard Home — stats, performance chart, activity, recent users
      • users.html → Users Management — searchable, sortable, paginated data table
      • reports.html → Reports — revenue charts with data-table alternatives, quarterly summary
      • settings.html → Settings — profile, notifications, security, accessibility prefs
      • components.html → Accessibility Demo — accordion, tabs, alerts, tooltips, dialogs

      Note: this deliverable bundles all five pages into one deployable file with client-side routing (hash-based), preserving identical semantics, landmarks and heading order per page. Split by data-page-panel blocks to recreate the multi-file layout below.

      Suggested folder structure

      project/ ├── index.html → Dashboard Home ├── users.html → Users Management ├── reports.html → Reports Page ├── settings.html → Settings Page ├── components.html → Accessibility Components Demo ├── css/ │ └── style.css → All styles (copy <style> block) ├── js/ │ └── script.js → All logic (copy <script> block) ├── assets/ │ └── avatars/ → Profile photos (or pravatar URLs) └── README.md → This documentation

      How to split this file

      1. Copy the <style>…</style> contents into css/style.css and link it.
      2. Copy the <script>…</script> contents into js/script.js and reference it with defer.
      3. Duplicate the file 5×; keep one data-page-panel per page and update aria-current.

      Run locally (VS Code)

      1. Save the file as index.html inside project/.
      2. Install the Live Server extension (Ritwick Dey).
      3. Right-click index.html → Open with Live Server.
      4. Visit http://127.0.0.1:5500 — navigate via sidebar or URLs #dashboard #users #reports #settings #components.

      Deploy to GitHub Pages

      1. git init → git add . → git commit -m "Accessible enterprise dashboard"
      2. Push to GitHub → Settings → Pages → Deploy from branch main / root.

      Accessibility features implemented

      • ✓Skip links, landmarks (header/nav/main/aside/footer), single h1 per page in logical order
      • ✓Visible :focus-visible rings (3px, 3:1+) on every interactive element
      • ✓Labels for all inputs; aria-describedby help + error text; aria-invalid on failure; error summary with focus
      • ✓Dialogs: role="dialog/alertdialog", aria-modal, focus trap, Esc + overlay click to close, focus returned to trigger
      • ✓Tables: caption/thead/tbody/th scope, aria-sort, scrollable role="region" with keyboard access
      • ✓Contrast ≥ 7:1 body, ≥ 4.5:1 muted; prefers-reduced-motion respected; live regions for toasts, counts & page changes

      • ✓<!DOCTYPE html> + lang="en" + charset + viewport + descriptive <title>

      • ✓All <img> have meaningful alt; decorative SVGs aria-hidden="true"
      • ✓Native <button>/<a>/<label>/<select> — no clickable divs
      • ✓Validate at validator.w3.org + axe DevTools: target 0 errors, 0 contrast violations
